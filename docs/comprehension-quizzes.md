2. Pull `teacher-role-feature` in the frontend and restart Metro with `npx expo start --dev-client -c`.

No dependency or package-lock changes, paid services, or dev-client rebuild are required by this JavaScript update. Existing published comprehension flags without a question set remain unavailable until the teacher finishes comprehension setup. Existing quizzes and accuracy/speed review are retained.

## Teacher workflow

Create a Reading Assignment, confirm its passage, and select Comprehension (with Read Aloud when both are assessed). Paste numbered questions, choices and answer keys together, or load a saved set matching that exact passage text and word count. Preview the parsed questions and choose `Use this reviewed quiz` before publishing. Changing the passage or reading-activity selection invalidates the ready quiz. The existing standalone Quiz editor remains available.

The publisher validates the quiz on the backend before creating the reading assignment. Configuration is then published against the server's confirmed passage. If the configuration request fails after classwork creation, the teacher is sent to Finish comprehension setup instead of creating a duplicate assignment. Classwork details contain Comprehension setup and Comprehension results actions. Published quiz configurations are immutable; use a new assignment to revise questions after publication.

Save reusable sets from Preview. Sets belong to the authenticated teacher and are only offered for matching normalized passage text and word count. Saved keys, expected-answer guides, rubric text and supporting-paragraph notes are teacher-only. Reusing a set still requires preview and confirmation; no questions are generated by AI.

### Paste format

```text
1. What did Mara plant?
A. A seed
B. A stone
C. A ribbon
ANSWER: A
POINTS: 1
SUPPORT: Paragraph 1

2. Select the two actions mentioned.
TYPE: checkboxes
A. Planting
B. Painting
C. Watering
ANSWER: A, C

3. The seed grew.
TYPE: true-false
ANSWER: TRUE

4. Why did the seed grow?
TYPE: short-answer
GUIDE: Expected answer for teacher review

5. Explain the lesson of the passage.
TYPE: essay
RUBRIC: Add the intended rubric and point criteria here
POINTS: 5
```

Each question starts on a numbered line. Choices and optional fields occupy separate lines. Supported TYPE values: multiple-choice (default), true-false, checkboxes, short-answer and essay. Essay requires RUBRIC. Teacher guides and SUPPORT notes are optional. Use 1–100 questions, 2–12 distinct choices, and positive points per question. Missing or invalid keys must be fixed before publishing. Checkbox grading requires exactly the answer-key set; order does not matter and there is no partial credit for objective items.

## Learner workflow

Open the reading activity from Classwork or To-do. When both activities are enabled, submit read-aloud first, then open Comprehension. The backend chooses and verifies the current reading submission rather than trusting a client-supplied attempt identifier. Comprehension-only assignments get an explicitly labeled standalone attempt, with no invented audio submission.

Answer one question at a time, use Previous/Next, and submit after all questions have responses. Drafts save after a short pause and on navigation/Save progress; failed saves display an error. Native Back and backgrounding attempt to save current progress. A dropped connection before a save completes still requires retrying; local success is never shown without a successful response. A revision check rejects stale writes from another session. Submitted responses are locked. Reopening the quiz returns the saved draft or result.

Passage access controls whether the passage snapshot is included and shown inside the quiz before submission. It is **not an exam lockdown**: previously accessed materials, other screens and external copies are not blocked. Teachers must choose settings appropriate to their assessment protocol.

To-do marks a combined assignment submitted only after the current read-aloud and comprehension are both submitted. Pending teacher grading counts as submitted learner work, not as a final grade. A replacement recording gets a new linked quiz attempt; prior attempts remain available for teacher audit and cannot be edited as the current attempt.

## Grading

Objective questions are graded on the backend. Short answer and essay remain pending until the owning teacher marks correctness and awards points according to the intended rubric. Every manual item must be graded before finalizing.

Comprehension percentage = correct questions / total comprehension questions × 100.

Quiz points are the sum of awarded per-question points, shown separately from the correctness-based percentage. They are not rescaled to the assignment's existing points field. Partial rubric points do not turn into fractional correct answers. No final comprehension percentage is emitted while any manual question remains ungraded. This module does not infer a Phil-IRI reading profile or alter existing speed/accuracy measures.

## Backend module

The supplied ZIP adds `models/Comprehension.js`, `utils/comprehension.js`, `routes/comprehension.js`, two tests, and `COMPREHENSION_UPDATE.md`. Only one mount line is added to existing `index.js`. Existing production models, classwork routes, audio upload/review routes, authentication and package files are preserved. New collections store quiz configurations, reusable teacher sets and immutable attempt snapshots; answer keys are private fields and all learner responses are explicit safe DTOs.

Endpoints under `/api/comprehension`: teacher validation (`POST /validate`), set search/create (`POST /sets/search`, `POST /sets`), teacher configuration (`GET/POST /classwork/:id/config`), learner availability/start (`GET /classwork/:id`, `POST /classwork/:id/start`), draft/submit (`PUT /attempts/:id/draft`, `POST /attempts/:id/submit`), teacher results/grading (`GET /classwork/:id/attempts`, `PATCH /attempts/:id/grade`), learner completion summaries (`GET /mine?classId=...`).

Role, classroom ownership, active enrollment, assignment, passage matching, reading-attempt matching and deadline checks are server-side. Teacher grading remains available after the due date. MongoDB must permit creation of the new collections and declared unique indexes before use. No production data is deleted or rewritten.
